## 已确认的基线缺陷

主代理在未修改基线上运行现有合成 GET/REPLY 报文，得到：

| 输入 | 基线事件 / 关联 | 要求 |
| --- | --- | --- |
| 完整请求响应 | 2 / 1 | 保留 |
| 同报文后 FIN、ACK | 1 / 0 | 完整观测不得被纯控制报文删除 |
| 再补双向 FIN、ACK | 0 / 0 | 正常关闭不改变已有消息 |

原始记录：`validation-round5/tcp-before.json`。上一轮八项 CI 成功已保留，但 `round4-completion-20261025.md` 已追记其覆盖缺口。修复还必须证明半关闭可接收响应、RST/重用不跨连接配对、非法关闭后载荷仍明确报告。

## 验收门槛

- 每次领取的身份和运行位置持久可追踪；缺失历史不可伪造。
- 所有相关 attempt 的有效退出证明齐备才 cancelled，缺项可诊断；旧 attempt 永远无法发布。
- 计算容器无法访问 API/数据库/协调器令牌、Docker socket 或控制回执；输入只读、输出限额。
- 持久发布前校验全部产物；中断不能产生假成功；同 attempt 重复交接可核验幂等，跨 attempt 严格隔离。
- packet 任务保留原帧、字段及图关联引用；成套恢复后重新查询，不以只有文件哈希替代引用核验。
- 前述链路通过后再推进网页证据和回放骨架；真实协议/双源时间对齐/工业效果仍须授权材料独立验收。

## 已实现但未完成验证或集成

- 独立隔离执行是opt-in承载，尚未完成所有旧任务类型的新旧产物一致性及生产迁移/回滚验收。

- 网页是本机只读最小入口，未接入正式用户鉴权、任务列表、双源时间线。回放是有界窗口骨架，未实现完整关联重算、水位最终确认、持久checkpoint和评估报告。

## 尚未完成及明确待处理边界

- docker create与execution登记间失效：从未启动的容器虽可清理，缺少合法登记时不捏造退出证明，任务保留pending；后续需not-started登记恢复协议。
- Docker已移除而移除回执尚未持久化时崩溃，无法自动确认则保持pending，需独立证据核对。
- 若整个本地job控制目录遗失，可显式指定recover-job从DB身份重建；自动跨主机全任务发现尚未实现。已登记不同daemon位置不会被本机猜测清理。
- 计算tmpfs有总量限额；宿主持久产物库还需容量配额、保留和清理策略。备份工具仅用于静止终态验证，非PITR/活动任务恢复或跨版本生产备份。
- Go发布验证原字节/范围/引用一致性；完整协议语义重算由隔离host、备份及查询Python校验执行。可信host/Docker daemon仍是边界，不能抵抗宿主root管理员篡改。

# R19 第一阶段：CSV 参考记录定位预登记

基线 `aa16a4db525e55d0c435fc16bad5bb5edbab94b6`。只推进参考定位，不改分析、匹配、RC1或R20。
原复核目录保持只读。原样运行 `probe_reference_locator.py`，结果保留于
`validation-round19-record-locator/original-probe-before.json`：三行CSV、正确文件hash和
`row:999999`在旧v2仍被接受，返回的是诚实的“仅字节已核、定位未解析”，确认为功能缺口。

## 新合同

- 显式 `evaluation-bundle-3`，沿用v2的128MiB文档、8MiB单原件/32MiB库存上限，不降低已有容量。
- 新引用 `{source_ref,sha256,locator}`；`locator`为
  `{version:'csv-logical-record-1',file_sha256,record_number,columns}`。
- 数据逻辑记录从1起计，表头不计为数据记录；0、负数、越界、不存在的记录拒绝。
- 固定首版为UTF-8（允许文件开头BOM）、逗号分隔、双引号/双写转义、LF或CRLF的CSV；不猜编码、分隔符或文件格式。
  文件名必须为`.csv`，实际内容须可严格解析；空/重复表头、坏CSV、记录宽度不符或必要列不存在拒绝。
- 必要列非空、唯一，并按原始列名精确匹配；不修剪值、重排源字节或将物理行号当记录编号。
- 按CSV解析器实际消费的逻辑记录边界保留原始字节片段，包括CRLF、引号和引号内换行，返回byte offset/size、片段sha及base64、物理行范围和所选列值。
- 同一文件的多个引用一次解析验证；文件sha、locator的文件sha、库存索引三者必须一致。
- 新freeze/result绑定定位器版本；evaluate、verify、query均验证引用，不能只在查询时补查。
- v1仍仅声明；v2仍仅原件字节已核且自由文本定位未解析，绝不自动升级。记录定位成功也不证明标注语义正确、外部独立性或保管链。

## 独立预期

|场景|预期|
|---|---|
|表头加两条数据，选择记录1/2|精确返回对应原片段；表头不是记录1|
|CRLF，第二条包含带引号换行和双写引号|仍为一条逻辑记录；offset、片段和解析值逐字节符合手写输入|
|最后一条没有换行符|返回末尾真实字节，不补换行|
|不存在、0、越界、缺列、重复必要列、未知版本|明确拒绝，不生成可信侧包|
|空/重复表头、坏CSV、宽度错、非UTF8、非CSV格式|明确拒绝|
|库存或locator文件hash错/片段字节变更|拒绝；重哈希外层也不能替代原件与定位核验|
|旧v1/v2相同自由文本引用|状态保持旧值，不获得record_verified|
|服务越权及恢复|越权先拒绝；源冻结后正式服务、完整备份、空库新目录恢复仍返回同片段|

新schema同时登记Go/Python；Go仅增加v3文档识别及数据库同预算放行，不改父任务的evaluation.go性能路径。
实现后先跑独立合同/核心/版本兼容测试；运行源码冻结并与父任务协调串行Docker后，再做正式服务与恢复。
所有失败与初次运行记录保留，正式测量开始后不无声改运行源码。

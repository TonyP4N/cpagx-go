# 第三轮：M2 协议适配与 M4 Worker 接入计划

基线 `292bb8af73ea508a8136acfce4e716937e6574f7`，分支 `refactor/m1-evidence-core`。开始时工作区干净；保留前两轮成果。

1. M2：在现有合成抓包容器适配器上增加独立 ENIP/CPF/CIP 明确子集，限定可解释字段和关联条件；覆盖合法结构、未知服务、损坏、重复/乱序/分段及无响应。协议事实以主源资料核对，合成夹具只能验软件行为。默认网络解析入口保持不变。
2. M4 Go 控制面：新增显式启动的内部鉴权 API，Go 唯一持有 PostgreSQL 凭据，限定共享目录、任务输入指纹、租约及 attempt 身份；完成前校验实际产物。兼容原型表与旧入口，不自动迁移生产。
3. M4 Python Worker：只通过内部 HTTP 领取/心跳/提交，用独立子进程调用同一纯核心；实现超时、取消、租约丢失后的停止，确认退出后才确认取消。不得接受任意用户命令。
4. 验收：先单元/契约，再真实 PostgreSQL 与真实子进程故障；验证 Worker 被终止后的租约恢复、旧 attempt 拒绝、重复完成、取消和损坏产物。合成新旧承载产生的标准事件/图应一致。未覆盖的磁盘/断电/恢复场景明确列项。
5. 分阶段提交及 push；记录实际 commit、测试日志、支持范围和下一步缺口。M2、M4 是否完成仍按原方案退出条件，不把本轮独立功能通过等同完整阶段完成。

分工：6.1-sol 协议适配代理、Go API/存储代理、Python Worker/故障代理；主代理负责接口协调、交叉审查、完整流程验收与提交。三个代理使用不同文件范围，先协定内部协议再集成。

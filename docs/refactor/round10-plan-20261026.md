# 第十轮有限计划：隔离探针取证稳定性

基线 `ee0cefa5a2a4907198ec6d158fdbac366760a00a`，当前分支 `refactor/m1-evidence-core`。本轮只修改合成隔离验证工具和回归，不切换默认入口，不重建冻结候选，不扩展协议、界面或业务执行范围。

| 条件 | 验收要求 |
|---|---|
| I1 复现旧探针竞态 | 复用真实容器，延迟宿主读取超过任务结束，记录旧 docker exec 无法取证；不得归因未经证实的产品退出失败 |
| I2 超时与启动分开 | 超时判定依据结构化退出回执和最终容器状态；正常启动快照、超时前未就绪须明确区分；不延长现有2秒计算超时来掩盖问题 |
| I3 双重崩溃 | 只有已获取完整就绪身份才发起双杀；确认容器退出且宿主PID为0；启动等待有界，失败保留日志与状态 |
| I4 稳定性 | 实际Docker重复至少3轮正常超时、延迟观察、延迟启动及双杀；原资源探针全套通过；缺失/损坏/不匹配回执负例必须失败 |
| I5 交付 | 本地回归及远端CI，保存逐轮证据，commit/push当前分支；冻结与默认入口不变 |

退出回执只证明对应执行组退出，最终Docker停止状态另证容器命名空间结束。没有回执不得补造；启动失败与超时前未就绪不得表述成正常启动。真实工业与历史任务材料缺口保持第九轮清单；M2/M4/整体仍未完成。

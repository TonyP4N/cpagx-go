# 第十六轮有限实施与预先验收条件

依赖：第十五轮首版清单/支持矩阵经源码核对并提交后开始实现。本轮仅统一数据、服务入口及权限；不实现 R17—R22 功能，不切换用户默认部署或冻结 RC1。

## 方案与边界

Go 提供独立显式启动的 loopback 公共 API 与现有构建静态站点；同进程使用另一 loopback 监听地址保留内部 M4 API。PostgreSQL 新增数据集、不可变文件/配置版本、运行绑定、用户会话/数据集权限和业务审计表。提交运行和绑定使用同一事务，沿用 m4_jobs 与既有 Worker/隔离核心，不另建状态机。Python 只承担既有预检/计算/证据查询。旧 V1/V2 默认部署保留；明确兼容适配范围，不让新版启动导入旧 FastAPI/Celery。

仅本机 HTTP，不承诺 LAN，监听非回环地址明确拒绝；LAN/TLS 留在首版清单的独立退出条件。真实来源与核验状态独立存储；真实文件可接收并完整性/元数据预检，但现有 synthetic-only 双源核心不支持真实分析，明确禁用。单源、映射或时间依据缺失保留接收记录及原因，不强制补齐或改成 synthetic。

## 预先定义的行为

| 条件 | 必须结果／禁止结果 |
|---|---|
| 完整合成 PCAP、CSV、版本配置 | 正常入口创建数据集→上传→预检→配置选择→持久执行→图/证据/下载，四条原始引用可核；不能当工业效果 |
| 来源类别缺失/非法 | 400，有明确错误码；不得默认 synthetic |
| 来源、授权、时间或映射说明不足 | 记录具体缺口，最多接收/单源核查；无跨源依据不得关联 |
| 实际真实材料 | source_kind=real、received/unvalidated，不自动变 verified；synthetic 核心执行拒绝 |
| 相同幂等上传请求 | 同一文件身份或明确重复响应；不得悄悄新增版本 |
| 同一幂等键不同字节、批次冲突 | 409；原记录和旧运行保持不变 |
| 原件变更或缺失 | 409 完整性错误；预检、运行、可信结果/证据/下载不得假成功 |
| 上传中断、声明哈希不符、超出上限 | 无已接收文件记录、无可信运行；清理本次临时文件并留失败审计；超限413 |
| 配置更新 | 新版本ID和指纹；旧运行仍绑定旧配置及文件，新运行绑定指定新版本 |
| 管理员 | 用户/ACL管理及授权数据操作可用；秘密不进入浏览器/日志 |
| 分析员 | 仅授权数据集写入/运行/取消，不能管理用户或越权数据 |
| 只读者 | 仅授权数据/任务/证据/下载可读；所有写操作403，直接API同样拒绝 |
| 未登录/跨数据集访问 | 401或不泄露对象的404/403；路径遍历与内部凭据不能绕过用户会话 |
| 终态备份恢复 | 新增目录/配置/绑定/ACL/审计随同一快照恢复；新空库/目录引用完整，旧会话统一撤销，重新登录后可查原始证据 |

## 退出条件及证据安排

1. Go 正式启动命令和 CLI 复用相同 `/api/v3`；OpenAPI、统一错误码和配置表与路由一致。
2. 真 PostgreSQL + 现有 Docker Worker：上述各场景有 API 集成证据，角色矩阵逐个允许/拒绝，不用 mock 代替关键链路。
3. 浏览器从正式 Go 静态站点开始，完成创建、上传、配置、预检、执行、图/四证据、受控下载；验证角色限制、缺材料和恢复后查询，无内部凭据。
4. 固定旧配置→新配置两个运行，对照数据库引用和核心 manifest；非法/中断上传不制造成功记录。
5. 成套终态备份新空库/目录恢复，目录引用与任务/attempt/原件一致；注入缺文件/篡改/绑定冲突明确失败；恢复会话失效并有审计。
6. 引用不受影响第十四轮证据；运行变更触及的契约、服务、备份、浏览器和相关回归；最终提交完整 CI 通过。
7. 更新首版清单三类状态与剩余项；不因本轮软件验收关闭真实数据适配、完整回放或后续批次。

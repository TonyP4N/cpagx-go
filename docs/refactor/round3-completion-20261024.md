## 已实现并通过测试

**M2**：增加独立 synthetic API/CLI，在现有 PCAP/PCAPNG 子集上读取 SendRRData、CPF、GetAttributeSingle / SetAttributeSingle 请求及响应原始状态。保留原帧 SHA256、偏移、帧号和原始字段。不输出攻击判断、物理动作或虚构标签。请求/响应仅在端点反向、session/context/service 一致且候选唯一时形成“抓包范围内匹配”；零 context、重复候选、序号重叠、未知载荷或 SYN/FIN/RST 边界禁用配对。

目前只接受一个完整 PDU 恰好位于一个 TCP payload 的情况。分段、合并 PDU、重组、连接生命周期推断仍不支持，必须与已实现字段区分。19 项抓包测试包含独立手写十六进制参考、PCAP/PCAPNG 生成夹具、响应错误状态、重复/乱序/损坏/无响应、连接边界和输入变更。参考来源为公开协议实现，不能代替授权真实样本或协议符合性验收。

**M4**：独立启动的 Go 内部 API 持有数据库凭据，Python Worker 通过 bearer 鉴权的 HTTP 领取、心跳、报告结果。每个 attempt 有随机 token 与递增编号；旧 attempt 不能提交。Go 在受控目录保存只读输入副本，校验配置/输入指纹、实际核心 manifest、产物哈希/大小后记录发布。重复完成必须重新验证，不能只看 succeeded 状态。新增迁移只增加列，现有生产入口不自动应用。

Worker 每次启动独立核心进程。守护进程通过父管道 EOF 发现 Worker 退出，包括 SIGKILL，清理计算进程组；只有确认退出才 ACK 取消。API 不可用或失去租约时停止计算、不提交终态。确定性输入/解析/配置错误不重试，超时/信号终止及服务端错误可在次数上限内重试。控制面凭据不传入守护/计算进程。CPU 时间、单文件大小、运行时长和日志上限有真实子进程测试；macOS 地址空间上限明确未启用。

真实 PostgreSQL + Go API + Worker 流程通过：

- 缺失/错误凭据、错误 attempt token 被拒绝；排队取消返回 cancelled。
- Worker 产出的标准事件/图与直接运行同一核心完全一致。
- 重复完成幂等；完成后的产物变更在再次校验时被发现。
- 超时、运行中取消后计算进程退出；取消 ACK 在退出确认之后。
- 实际 SIGKILL Worker，独立守护进程清理子进程；等待真实租约到期后 attempt 2 成功恢复；旧 attempt 提交被拒绝。
- 损坏产物不能发布。
- 独立数据库容器重启后，API 重连并读取已有终态及已发布 manifest。

## 兼容与停用验证

旧入口没有改为新 API。停止本轮手动启动的 M4 API 和数据库后，原 `http://127.0.0.1:13000` 提交→Go→Python/Celery→核心→下载回归通过，任务 `4617c4cc-bc2b-412a-b4c6-0cd6975b65ee`，5 项下载可读且 manifest 中 4 项产物校验值匹配。既有输出保留。

因此本轮可通过停止显式启动的新服务停用增量能力。尚未进行生产默认切换，不能把此结果称为生产数据库迁移回滚或灾难恢复验收。旧组件继续保留。

## 未验证能力与剩余问题

- M2 代码仅合成验证；真实 ENIP/CIP 字段正确率、设备支持范围、链路/时钟、工艺映射和工业效果均未验证。TCP 有界重组、复杂 CIP 路径/服务、连接生命周期及 checksum 校验尚未实现。
- M4 发布校验/输入副本已实现，但数据库与文件系统不是统一事务；崩溃可留下待核对文件，自动孤儿文件核对/回收未实现。文件 Sync 不构成目录持久化、断电或完整备份恢复证明。
- 共享目录依赖可信操作系统身份与权限；同一文件属主仍可能修改数据。已发布产物的消费者也必须核对校验值。尚无公共用户权限/多角色 API。
- Worker 单独 SIGKILL 已验证；Worker 与守护进程同时被杀、恶意子进程逃逸进程组等场景需要 Linux 容器/cgroup 或服务管理器兜底，尚未验收。聚合内存、磁盘配额、长期压力与完整资源预算未完成。
- 失联后 cancelling 的任务不会仅凭租约到期被武断宣布取消；需要可靠恢复器确认进程退出，目前仍待实现。领取恢复仍由下一次 claim 触发，没有独立定时回收 SLO。
- PostgreSQL 容器重启已测；数据库断电/磁盘损坏/备份恢复、网络分区下长期一致性、迁移与生产回滚尚未验收。

# R21 单机部署与运维验收

基线 `9b213a0df88bd0019e2ff7ed04c8b692e3ad4880` 与远端一致，[R20 CI 17/17](https://github.com/TonyP4N/cpagx-go/actions/runs/41771812399)。按收尾路线图第 21 轮和首版支持矩阵，选择一台 Linux 主机承载正式服务。Windows 客户端只需浏览器。操作步骤见[部署操作说明](round21-operations.md)，检查结果见[证据索引](validation-round21/index.json)。

| 条件 | 验收口径 |
|---|---|
| 目标站点 | 记录实际主机发行版/架构/持久盘、运维授权、入口域名、DNS 和证书管理人、反向代理、首次管理员交接及独立 Windows 测试方式。公网受信 TLS、重定向、续期、独立 Windows 浏览器均须取目标现场证据。 |
| 隔离部署 | 一套固定配置，Go/Worker 冷启动三次，逐次核对就绪与既有数据，只做一次完整合成业务烟测；记录 Linux 实际环境与代理信任边界。 |
| 故障与恢复 | 数据库、存储、中断、发布竞争、取消和超时；停写后拒绝新任务，拒绝未退出执行，成套恢复到空库和新目录，新会话重新核验。 |
| 历史 | normalized 五件、packet 六件、双源十一件的原件及清单；核对受控读取、拒绝篡改以及旧入口路径；无实际历史实例时使用标记的合成样例。 |

**本地定向复验。** 注入“数据库可能已完成提交、客户端未收到确认”时，原上传处理返回 409 并删除唯一源文件。修复后返回 503 `commit_unconfirmed` 并保留文件；上传者使用同一幂等键重查，配置提交者重读版本列表。目录项在数据库提交前同步。可确定回滚的写入失败仍可移除本次新建文件。该回归通过 database/sql 驱动注入，不冒充目标机器断电实测。

正式旧 M4 任务没有数据集 ACL。新增只读入口限当前已登录管理员，按已发布成功任务、attempt 和数据库内容锚点读取，不允许业务用户提交文件路径。逐件核对原件、配置、工件库存及摘要，下载使用有界私有副本。独立实例上 normalized 和 packet 各一次 attempt 1 成功，分别核对 5/6 件工件、8/2 个观测。两者均实测匿名 401、无授权 403、写入 405、未知成员 404、同大小改写已绑定原件 409；恢复原字节后下载摘要一致。首次篡改注入改到了提交前的暂存文件，服务仍能读取已固定的原件；修正注入位置后通过。这些已发布 M4 任务的权限边界与 V3 数据集 ACL 分开。

旧工作区与新工作台经同一正式服务打开，前后重读既有运行及下载的历史图。V1/V2 原路由由原网关负责；控制请求不从公网代理到内部 Worker。旧版 Celery 的真实队列执行及篡改下载拒绝引用 [R9 验收](round9-acceptance-20261026.md)，终态 DAG6 恢复及冷核验引用 [R19](round19-shared-backup-acceptance-20261102.md)。R19 固定 S100 三组和 R20 图规模不重复运行。

十一件双源导出另用一个正式小任务验收：首次执行成功，逐件通过原 V3 下载端点核对摘要，打开旧工作区和工作台后可再查同一结果。旧 Gin 网关的实际路由注册与两个受控 HTTP 上游核对通过，覆盖 `/api/v1/cpag/result/:id`、`/api/v2/cpag/result/:id` 和 `/api/cpag/result/:id` 归属 V1；这项是代理契约检查。旧独立服务继续按原软件和数据环境启用，不能在新公网域名把无鉴权 V1/V2 网关直接开放。已有 V3 数据集的双源结果始终按数据集 ACL 下载；无 ACL 的 normalized/packet 已发布结果另走管理员只读路由。

**外部交接。** 选择正式单机 Linux 方案。目标服务器的授权连接引用、CPU 架构及持久目录、可用域名、DNS/证书/反向代理负责人、管理员首次登录安全交接渠道及独立 Windows Edge/Chrome 测试终端尚未提供。管理员经既有安全渠道交付访问引用；DNS/证书管理人完成解析和受信证书后，用独立 Windows 登录并记录版本、实际 URL 与四条证据。这些条件与 Ubuntu 指定性能参考环境、社区 M/L、真实工业双源材料和真实历史实例分别登记。

**保留策略。** 所有原件、运行产物、未确认执行、失败任务及退出证明保持受控。数据库无法确认的暂存或孤儿文件由停写快照列出，须由运维核对历史引用；不自动删除或隔离。管理员可调整已轮转日志和明确关闭临时文件的保留天数。备份保留数量用于预览待审旧包。清理的生效范围和回执以部署命令及本轮实测为准。

**可重复的小检查。** `go test ./internal/catalog ./internal/jobapi ./api`；`PYTHONPATH=services/analysis/src:. python -m unittest discover -s tests/compatibility -v`。历史三格式端到端脚本为 `scripts/validation/round21_history.py <独立R20旧回放验收目录>`，只在其识别的专用环境内运行。单独启用旧网关进行回退时须保留其原 V1/V2 上游及持久目录，仅允许受控访问；R21 网页、数据库与新产物继续保留。切换网页入口没有覆盖或转换业务数据。

**运行观测。** `/health/live` 仅表示进程响应；`/health/ready` 要求 DB 在2秒内响应、shared inputs/catalog/jobs 和 control 目录可读写遍历且未变为符号链接/只读文件系统，各文件系统可用空间至少64MiB。该最低就绪余量不代替 Worker profile 更高的执行空间门禁；检查不写入不可变库存。管理员查询 `/api/v3/health/operations`，匿名401、viewer/analyst403，返回 eligible 排队等待、退避/重试、Worker 观测、磁盘、保留错误分类及 alerts。查询期限3秒，错误分页最多100，Worker最多100；队列等待从 eligible `available_at` 计算。默认 Worker 陈旧阈值120秒兼容最长60秒 idle 轮询，排队告警60秒；可用有界参数调整且响应回显。旧 schema 缺017时明确503 `operations_schema_not_ready`，不把不可观测当空成功，也不改变旧 claim/heartbeat 权限与结果。

Worker 瞬时表只接收认证且通过校验的 claim 轮询或有效 heartbeat，`last_kind` 区分两者。过期/坏凭据请求不刷新；观测不授予租约或发布权限。备份恢复在服务启动前清空该表。错误类别仅分类当前保留的 `last_error`，不等于故障事件速率；原始原因仍走既有授权 run 状态。alerts 是查询条件结果，不声称已送达外部通知。

新隔离 PG、当前 Go 与真实 idle Worker 的短检查通过（短故障样本显式用2秒Worker陈旧阈值、1秒排队阈值，未把它写成默认120秒条件的检测延迟）：fresh poll、有效与过期心跳、坏凭据不刷新、队列等待/Worker 缺失/租约过期告警、合成控制平面记录的重试和 parse 去敏查询；暂停该 PG 时 live200/ready503（约2.003秒），恢复后 ready200；必要目录移走时 live200/ready503，恢复后 ready200。前两次夹具失败分别是 PG 初始化临时 socket 误判和静态根 Path 参数错误，原始失败保留，修正夹具后通过。解析错误样本由真实内部 fail RPC 提交，仅验证控制平面分类，不冒充新解析器执行。

另外在固定 Linux/arm64 镜像的非特权、无网络、只读根容器内执行当前 Go 存储检查：只读挂载实际写入返回 `EROFS`；8MiB tmpfs 写满实际返回 `ENOSPC`，检查均报告存储不可用或空间低。容器128MiB内存、32 PID，测试字节上限16MiB；已确认退出并删除。这不等于在最终 SQLite 中途写入处杀进程。新证据的必要字段和原始目录位置均见同一[证据索引](validation-round21/index.json)的 `observability`。

**审计解释。** 管理员从 `/api/v3/audit` 查询操作者、数据集或运行、动作及结果。上传带服务分配的文件 ID，配置带版本 ID，授权带目标用户 ID/授权级别，已核验的产物下载带清单成员名。下载 `ok` 记录服务已通过授权和字节核验并准许发送；客户端收到完整字节以下载摘要或代理实际发送字节核对。执行身份与退出在运行 attempt 历史中查询。维护停写后没有用户会话，备份、恢复和清理以受保护运维回执记录部署 ID、实际 uid/euid 和结果。

**独立浏览器普通流程。** 在 Linux 容器服务之外的 macOS arm64 客户端，用 Chromium 156.0.8078.80 普通点击 `https://127.0.0.1:44943` 完成登录、两份抓包和一份CSV上传、预检、唯一一次离线提交；关闭页面、退出再登录后找回同一运行，逐一打开4条原始记录，再点击原抓包和 `run_manifest.json` 受控下载并核对SHA-256。跨恢复尝试合计只有1个数据集、3次上传、2个配置版本、1次预检和1次运行提交；没有重起一批任务，也没有业务API写入注入。会话cookie为 Secure/HttpOnly/SameSite Strict，无页面错误；临时浏览器配置已删除。前两次观察器无法从CDP重读二进制POST响应体、第三次把原生select的option当可见元素等待，均保留失败报告；改用HTTP状态加页面ID/SHA并复用原对象后通过。

证书验证与点按分开：未配置例外的全新Chromium先按预期报 `ERR_CERT_AUTHORITY_INVALID`。严格 `curl --cacert` 与独立 Node TLS 的显式测试CA、主机名检查均通过，TLS1.3且同一叶证书 SHA-256 为 `9203952c29dae8bea45e89ec2b136b384a934772b4fedda3d23cafa3a463e162`。浏览器点按会话只对该叶公钥设置临时SPKI例外；没有修改系统keychain或永久信任，不能写成浏览器CA受信、公共域名PKI或Windows客户端验收。Chromium的该选项会跳过匹配公钥的证书校验，行为依据其[官方实现说明](https://chromium.googlesource.com/chromium/src/+/8402d3c5bc13e018fa75eba650ed881755e0223b)。普通功能与严格链验证的各自边界、前次失败和两张脱敏截图都登记在唯一索引的 `https_browser_external`。

**停写、成套恢复与恢复后查询。** 独立 Linux 部署先实测在线备份被维护锁拒绝，保留失败回执且未发布有效包；随后停止 Go/Worker，以固定独立运维包为实际 `cpag_app` 建立格式7备份，再恢复到新库 `cpag_restore` 及新 `/var/lib/cpag-recovery/{shared,control}`。29个业务文件、47个控制文件，完整包实际76,219,265字节（其中业务75,745,813、控制217,450、PG dump 81,006字节，其余为清单等）。从在线拒绝回执到成功备份包约62.034秒，包含停机与工具编排，不能当作纯备份耗时；恢复约1.754秒，按同一Linux墙钟的root审计预约时间戳至最终回执mtime推导，不是单调时钟性能验收。

恢复的任务、完整attempt、目录、发布、文件及控制库存审计通过；11个旧会话撤销，Worker瞬时观测1条清零。恢复及限定清理后，原 `cpag_app` 任务/attempt、原shared和完整control仍保持，未覆盖源库或原目录。仅新恢复目录交接给既有服务UID1001，备份根保持root:root、0700；随后通过独立恢复配置启用同冻结运行时。恢复后实际HTTPS查询单独验收：真实备份前会话先200、恢复后401；重新登录后，同一离线和回放均保留attempt1，冷核验由409转200，回放4条原件及TP1/FP1/FN1可再读；已授权viewer/analyst受控下载的SHA-256一致。这些是正式服务复核结果，与运维工具的存储审计成功分别记录在唯一索引 `deployment_restore`。

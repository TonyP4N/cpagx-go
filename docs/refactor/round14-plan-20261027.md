# 第十四轮：双源持久任务与恢复验收计划

基线：23635e90922adcfd0eb2c20e3ca620b31e5d72fb；当前重构分支。冻结 RC1、默认入口和已有验收保持不变，仅接通既有双源核心。

1. 契约阶段：显式 dual-source 任务、三份输入、小数时间配置跨语言指纹、DerivedEvent、嵌套证据和 attempt 身份；非法输入、篡改、过期发布均拒绝。
2. 一致性阶段：同一合成输入经 Celery 与持久 Worker，比较事件、图、候选关联、反证、未知和原始证据；排除字段必须记录依据。
3. 故障阶段：实际验证排队/运行取消、Worker 中断、租约失效、重复提交、服务重启；保存退出依据、旧 attempt 拒绝及重试仅发布一次记录。
4. 恢复阶段：限定停写且任务终态；备份数据库任务、执行历史及所有输入配置产物证据；空库、新目录恢复后通过 API 与现有界面查询四条原始证据，缺失篡改拒绝。
5. 交付阶段：分阶段提交，运行受影响回归及浏览器验收，最终 CI 通过并推送；更新 M4/R09—R10、R13 状态和剩余退出条件。

显式选择持久执行，Celery 保留对照。真实材料单列，只读接收不得标成 synthetic。本轮不扩协议、算法、完整回放或跨主机能力，不重打包 RC1、不切换生产默认。文件目录恢复不能代替数据库恢复，退出证据不足继续待处理。

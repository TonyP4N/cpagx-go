# TCP 关闭缺陷修复验收

2026-10-26，基线 d4974c0，合成抓包限定支持子集；协议范围未扩大。

主代理复现：完整请求响应 2事件/1关联，追加FIN/ACK变1/0，双向关闭变0/0。问题来自连接共享closed标记及在判断载荷长度前污染整个方向。`validation-round5/tcp-before.json`保存原结果。

现在按连接epoch和两个方向分别维护FIN；纯ACK/FIN/RST只记录控制观测，不能删除已解析完整消息。半关闭允许对向响应，双向FIN或RST后新增数据明确拒绝；新SYN划分连接，重复SYN及匹配SYN/ACK在握手期间保留同epoch。控制载荷仍不支持，冲突FIN和非法关闭后数据阻止该epoch关联但不抹去已有有效观测。无SYN的关闭后数据不被猜测成新连接。

主代理复测相同三组输入，全部2事件/1关联（`tcp-after.json`）。回归同时覆盖正常关闭、半关闭响应、重复FIN/ACK、RST前既有观测、RST后载荷、连接重用、重复握手，以及不同epoch相同context不可配对。已有分段/乱序/重传/冲突/资源上限测试继续运行。

这些证明有限合成夹具下保留有效观测并避免已测跨连接误配；不表示完整TCP状态机或真实工业协议验收。缺失SYN、抓包顺序与时间映射仍是明确限制。

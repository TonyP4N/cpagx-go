## 实际能力及支持边界

统一复用 `packet_pipeline` → `dual_source`，Go公共服务、PostgreSQL持久任务、隔离Worker、CLI沿相同核心。最多四抓包共享连接epoch、分段/重组与请求响应匹配，引用使用原文件哈希和本地帧号；显式输入顺序进入运行绑定与指纹。新版配置启用 `bounded-real-capable-v1`，新增时钟精度/漂移/有效期、映射版本/有效期/歧义及三种有限规则。真实来源保留 false 标记和未核验状态，并受来源、批次、授权、映射、时间材料门禁。

事件、图、质量、有限规则、证据、下载、不可变预检和成套终态恢复使用相同来源及配置契约。页面只补来源状态、规则及证据入口和多文件顺序说明。候选关系仍是假设；成功响应不是物理成功，不给攻击或因果结论。

完整子集/限额/操作：[round17-operations.md](round17-operations.md)。实际执行为四抓包合计16MiB/10000帧、CSV2MiB/1000逻辑记录；首版候选的每件64MiB/合计128MiB、CSV8MiB/10000记录不变，完整容量性能仍待R19。XLS/XLSX仍接收待转换，不能直接分析；未知链路/布局明确拒绝，不虚构替代事件。

## 发现、失败与修复

完整失败尾部记录保留在 [failure-history.json](validation-round17/failure-history.json)。

1. 新版缺漂移/精度材料可能沿用旧零值假设：新增模式缺材料改为未知，不关联；旧配置语义单独保留。独立缺字段测试通过。
2. 新版重复CSV/不支持PDU修正会改变旧产物重算：同算法增加显式版本行为；旧默认不变。原基线生成的三类边界历史导出，当前核验成功且全部文件字节不变；正常15场景亦相同。
3. Go有限规则证据查询未识别finding：整链复现409，补查询和每条finding的HTTP测试，随后实际Worker/浏览器通过。
4. SQL NULL抓包数组导致旧单文件GET误报404：R16正式回归复现，修复标准byte slice扫描；scalar/multi HTTP回归和完整R16流程通过，独立修复提交de257ce。
5. 开发中镜像与宿主核心版本不同步：完整性重算正确拒绝发布；冻结后重建镜像，正式三次运行通过。未将该失败算作验收成功。
6. 验收脚本两处夹具问题：上传幂等键太短、迁移测试缺必填max_attempts；按既有契约修正，未降低生产约束。真实PG迁移008应用两次及所有权/角色/重复/数量/删除保护检查通过，[migration008.log](validation-round17/migration008.log)。

本地受影响Go全量、核心/契约、解析、双源、Worker、隔离、备份、前端构建通过。备份最终去除重复加载的测试类后47项通过，早期子报告60项包含重复收集，不作为能力增加依据。R16补验收20项操作顺序及普通点击拒绝/恢复均通过，结果见本目录 `r16-*`。最终完整CI仍是本轮关闭必要条件。

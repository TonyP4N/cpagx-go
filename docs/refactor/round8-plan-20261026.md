## 3. 下一阶段有限实施清单

执行顺序：先 P1，再 P2，最后 P3；P2 的只读盘点可与 P1 并行。P3 依赖 P1 的输入身份和指纹定义。每项先核对已有实现，再补缺口；影响本项验收的缺陷先复现修复，其他风险登记后续，不扩大本轮。

### P1：数据接收预检与材料模板（R05、R06）

交付：离线预检 CLI、接收清单模板、批次配置模板、机器可读及人工可读报告、合成负例测试。复用 DatasetManifest、现有哈希/路径校验，不新建第二套来源真相。

只检查文件完整性和声明元数据，不自动下载、解压或修改 raw，不自动推定数据年份、时区、设备映射；不会绕过核心 synthetic-only 限制。预检成功只表示可进入人工接收核查，不表示解析准确或双源验收通过。

验收条件：

1. 合成完整包产生固定结构报告；缺文件、校验值不符、越界路径、冲突批次及不受支持格式分别给出明确原因与退出码，不能报告 ready。
2. 授权、时间依据、映射不全分别列为材料缺口；无法核验的时间范围标记 unknown，不能凭声明把两源视为已对齐。
3. 单源可记为“仅可进行该源核查”，双源检查仍受阻；不向目前要求双源的执行入口提交空源。
4. 全部输入内容在预检前后哈希不变；报告不包含凭据或受限下载链接；文件存在不等于获得使用授权。
5. 合成样例与真实材料目录分离；相同输入/配置三次运行的规范化报告相同，易变运行字段单独登记。

### P2：旧能力清单与兼容差异归因（R01、R09、R10）

交付：从现有路由、CLI、任务定义、产物读取入口生成可追溯的有限清单；每项记录“共享核心 / 旧版独有 / 新版独有 / 明确不支持 / 待材料核查”，附代码位置和测试命令。清单在执行测试前固定，不为数量增加测试。

验收条件：

1. 列入清单的每个入口都有测试结果或具体阻塞原因，不以“未知”代替未盘点。旧版失败如实记录，不模仿错误结果。
2. 共享核心复用 round7-consistency 的逐字段允许差异规则；每项三次规范化事件、图与证据比较一致，或提供可复现差异、原因和处理决定。不得广泛剔除 ID/时间/哈希以掩盖差异。
3. 新版独有抓包能力按独立契约验收；不强迫旧版产生相同结果。旧版独有且不支持迁移的能力明确保留旧入口。
4. 历史结果只读能力只针对明确列出的格式验证；缺文件或不兼容版本明确报错，测试前后历史文件不变。真实历史实例缺失时，只能记合成格式通过、真实实例待核查。
5. 默认配置、任务归属、冻结标签及包校验值不变。不要求迁移所有历史中间文件，也不以退出旧服务代替兼容验证。

### P3：独立评估契约与泄漏防护（R08）

交付：复用 EvaluationRecord 的独立 annotations/splits 契约、评估 CLI、隔离说明、人工可算的合成指标夹具。盘点既有 evaluation 脚本是否从预测构造 gold；未检查前不判定其有缺陷，检查发现则记录证据并禁止其作为本轮参考。

验收条件：

1. 分析输入只含数据及冻结配置；测试标注仅评估器可读。改变测试标签不得改变同一分析输入的规范化输出；尝试将 annotations 路径传入分析侧必须被拒绝或隔离。
2. 按批次/连续时间块划分校准与保留集，重叠、跨集合重复样本及边界隔离不足自动失败。隔离长度至少为所有启用规则的最大窗口；窗口未声明时拒绝生成可用于正式评估的划分。
3. 评估器可对外部提供的合成预测计算指标，但不新增预测算法。TP/FP/FN、事件匹配容差、正常小时分母、空集合和除零均有手算结果测试；没有正常时长不能输出误报/小时数值。
4. 未标注边及争议区间单列，不能自动当负例；没有独立路径 gold 时不输出路径准确率。未经校准的分数不显示为概率。
5. 报告包含来源、标注版本、划分及输入/配置指纹；默认明确 synthetic。无真实标签时正式 precision/recall 等结论为“未评估”，不能填合成得分作为真实成绩。
6. 参数及指标阈值在保留集解封前登记；本阶段不设工业 F1、吞吐或毫秒级效果承诺。

| 材料 | 用途及最小要求 | 缺失时仍可做什么 |

| 时钟依据 | 时区、时间精度、同步方式、已知偏移/漂移或可信公共事件 | 保留独立时间线；不启用依赖对齐的跨源规则 |
| 正常和攻击区间 | 至少一个正常区间和一个攻击区间，与该批次匹配的正式攻击说明 | 解析接口与质量报告测试；不能通过 M3 独立复核 |
| 独立标注和保留集 | 标签来源、审阅/争议记录；开发与保留集隔离，分析侧不读测试标签 | P3 计算与泄漏测试；不报告真实效果或调参 |
| 旧任务材料（条件性） | P2 盘点发现本地缺失后，集中列出具体任务格式、实例、配置；不要预先要求全量历史数据库 | 已有共享核心比较、合成历史格式验证；缺失实例保留未核查 |

真实材料不进入公开 Git/CI。先验证授权与文件身份，再核查单源字段，然后校准时间/设备映射，再进行双源正常/攻击区间复核，最后在冻结参数下解封保留集。公开规则仅作参考，官方攻击时间也不自动成为完整关系图 gold。

## 6. 后续候选工作，不纳入本阶段

1. 有界顺序回放：水位、迟到窗口、修订历史、重启恢复和无未来读取测试；真实延迟评估另待到达时间依据。
2. 证据与时间线界面：通用任务授权、图到原始证据联动及原方案建议的 1000 节点/3000 边交互测试；本阶段继续暂停界面扩展。
3. 固定硬件性能基准：复用现有 evidence benchmark，登记吞吐、峰值资源、积压，阈值在测量前约定；不把建议的8vCPU/16GiB当最低配置承诺。
4. 扩大工程目标环境及运维：裸机/VM安装、其他架构、角色授权、监控与保留策略需要独立有限范围，不回写本轮冻结包；跨主机不默认纳入。

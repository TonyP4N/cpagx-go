## 定位和修改

历史记录直接引用 round19-core-bottleneck-acceptance-20261028.md：S 回放导出约 1103 秒，来源核验耗尽剩余预算，整链约 1801 秒失败。存储、投影与引用遍历是嵌套成本，不能直接求和。

第一种完整平坦列表缓存诊断由 8.418 秒恶化为 13.105 秒，已撤回，结果保留。实际采用两项不改业务/存储格式的优化：

- `references` 在单次同步调用内跳过已遍历容器；所有唯一原始引用仍按完整规范字节去重排序。集合在返回时丢弃，不跨输入/调用复用。
- `bounded-pure-node-hash-1` 对纯节点哈希函数复用全部参数相同的结果；键包含 kind、完整 payload、size、items、height，最多4096项、每项 payload 不超过1024字节（payload 上界4 MiB，另有有界 Python 元数据）。不缓存来源核验成功，不替代数据库或原件检查；大节点照旧计算。存储摘要及旧格式不变。

固定60步诊断：完整快照/修订根全部相同，3.262→2.719秒。只是部分前缀来源计算，不是正式容量验收。第一次诊断试图导出未结束输入，被现有 input_not_exhausted 正确拒绝；后改为只核对前缀的源计算根，不生产可信产物。首次小例在 iCloud 工作目录触发 evidence file changed，保留失败；移至独立本地临时目录后重验，未放宽完整性检查。

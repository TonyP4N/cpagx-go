# R19 服务内发布核验复用（实施中，非验收结论）

策略版本：`service-publication-verification-reuse-1`。不改变分析、评估统计、旧产物或旧 bundle 的版本语义；不增加 HTTP 等待预算。仅改变已核验的服务请求内重复计算方式。

## 信任边界

Go 在现有数据集授权后验证数据库当前成功发布、attempt、输入及产物全部字节和库存；从已核验库存取得 run_manifest SHA，通过内部子进程参数传递。外部请求、标注和保存文档不能提供或覆盖该参数。Python 校验此 SHA，并逐件重新计算字节哈希；同一子进程内可以复用解析后的不可变分析，不重新运行关联算法。Go 返回前再次验证当前发布及字节集合。

这个摘要本身不是签名，也不能证明任意 CLI 调用者的授权。内部选项只接受受信任服务的先验核验结果；正常 CLI 不设置它，继续执行完整语义核验。缓存不跨请求、进程、服务重启或用户复用。缺失、同大小篡改、库存路径异常和发布变更均拒绝。

原始证据查询仍通过相同原始帧/逻辑记录解析器核验原件及字段，只省去先前重复的完整分析。旧版本保留其历史判断；复用不重写结果。

## 测前退出条件

1. 同一夹具的独立 CLI 与服务内投影、错误实例、引用内容逐字段相等；不能只比较数量。
2. 正常 CLI 仍调用完整语义核验；内部上下文退出后不留下信任状态。
3. 上下文建立后同大小篡改、删除文件、错误根目录或 manifest 摘要均拒绝，即使已命中请求内缓存。
4. 正式 S100 HTTP 在新服务进程（应用冷缓存）和热缓存下完成输入、导入、详情、下载和原件查询；全请求小于10秒。OS冷缓存未控制时标为未验证。
5. 权限变化、当前发布 attempt 变化、服务重启及成套恢复仍通过既有服务端边界。

内部微测或 Python 单测不等于第4、5项完成；实际HTTP记录另存，失败不覆盖。回放及大规模是否需要额外受控准备机制，以正式测量决定。

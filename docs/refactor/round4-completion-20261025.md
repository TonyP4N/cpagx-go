## 本轮成果与边界

1. **独立恢复**：Go 恢复进程直接周期检查 PostgreSQL，不依赖新 Claim 或 API；正常条件下每秒扫描，取消五秒后进入核验，数据库每轮上下文十秒。缺失、错误或过期退出回执保持 cancelling 并记录原因。真实 PostgreSQL、实际 Worker/guardian、API 中断、Worker SIGKILL 和无新任务场景见 [恢复记录](round4-recovery.md)。这些是可运行服务条件下的检查周期，不是无条件恢复 SLA；数据库/共享存储不可用不承诺截止时刻。执行过但重新排队的任务取消也必须等退出证明；attempt>1 因缺全历史证明保留 cancelling、需人工调查。退出回执目前仅覆盖可信核心与同进程组后代，容器停止证明与任务状态的自动接线仍待完成。
2. **协议证据链**：原始 PCAP/PCAPNG → 有界 TCP 重组 → ENIP/CPF/CIP 子集观测 → NetworkEvent → observed 图 → 原始帧和字段查询已贯通。30 项测试涵盖分段、合并、乱序、重传、冲突、缺口、连接边界和资源限制。关系仅为协议请求响应关联，不推导攻击、因果或物理成功。CLI 为最小证据查看入口，生产 API/网页联动未接入。见 [协议记录](round4-protocol.md) 与 [解析器取舍 ADR](adr/004-bounded-packet-stream.md)。
3. **Linux 隔离**：实际容器七项测试通过，覆盖 OOM、CPU 配额、PID 上限、运行/输出磁盘写满、实际 Worker 超时及 Worker+guardian 双杀。容器停止清理包含 setsid 逃逸后代。它是独立技术验证；同 UID 控制回执、防护控制目录、持久产物交接、宿主机/daemon 故障尚未收敛。见 [Linux 记录](round4-linux.md)。
4. **成套备份恢复**：实现终态任务一致性快照、输入/产物哈希及逐条证据引用核验；具体实际恢复与负例结果以 [备份恢复记录](round4-backup.md) 为准。孤儿文件保留并报告，不自动删除；不支持活动任务在线备份，不作为生产恢复方案。

上一轮远端六项 CI 已核实全成功，已同步修正 [第三轮验收](round3-completion-20261024.md)，证据见 `validation-round4/prior-ci.json`，工作流 [40081915810](https://github.com/TonyP4N/cpagx-go/actions/runs/40081915810)。

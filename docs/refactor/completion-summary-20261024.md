本次依据《CPAG 系统化重构方案 v1.0》完成了不依赖真实数据的核心基础建设，并贯通本地合成任务的提交、队列执行、结果查看和下载流程。这是阶段性工程交付，不表示整份重构方案已经完成，也不构成真实工业数据验证。

## 一、资料与架构基础

- 解压 SWaT 参考资料包，先阅读 README、数据版本目录、下载清单和待获取事项；18 份已下载资料的大小与 SHA-256 均匹配，包内校验清单核验通过。
- 明确资料包不含原始 PCAP/PCAPNG、Historian 时序和配套正式攻击记录。公开规则只作参考，不作独立标准答案。
- 固定代码基线，建立独立重构分支，保留 Go、Python、TypeScript 的技术路线。
- 建立架构决策记录：Go 管理服务与任务，Python 负责纯分析核心，前端负责呈现；Neo4j 为可选适配方向。PostgreSQL 与租约任务系统仍属后续阶段，未替换现有 Celery 承载。

参考资料包保存在仓库外；本次提交包含来源核验记录和批次索引，不包含资料包全文、受限原始数据、授权下载链接或本机运行数据目录。

## 二、核心、契约与解析接口

- 定义 DatasetManifest、Asset、NetworkEvent、ProcessObservation、DerivedEvent、Claim、GraphArtifact、RunManifest、EvaluationRecord 九类版本化 JSON Schema。
- 增加 Python 与 Go 契约校验、共享合成样例及独立 JSON Schema 校验测试。
- 建立无数据库、消息队列或 Web 框架依赖的 Python 核心 API/CLI。
- 实现显式 synthetic 网络 JSONL 适配器和配置驱动 CSV 适配器；保留原始时间、逻辑记录号、列名、文件哈希、缺失值与未知原因，不默认补零或插值。
- 输出独立观测、图、数据质量报告、数据集与运行清单；产物带校验值，运行目录禁止覆盖，规范化结果可重复。
- 合成示例包含 8 个观测节点、0 条关联边、0 个推断。它验证观测与证据输出，不代表已实现跨源关联。
- 新 PCAP/PCAPNG 入口明确不支持；旧 V2 普通 PCAP 的按包序号伪造设备、标签与事件逻辑已移除。

## 三、本地全栈与完整任务流程

已实际启动 Go API、Python V1/V2、Celery Worker、静态前端及同源代理，以及隔离 Docker 项目的 Redis、RabbitMQ、Neo4j、InfluxDB。基础服务均通过健康检查。

新增显式选择的合成任务入口，三份文件经 V2 HTTP 上传后，由真实 RabbitMQ/Celery 队列调用同一核心。完成后可查询状态、查看结果并下载 graph、events、dataset、quality 与 run_manifest 五份文件。旧版默认分析入口未被替换。

网页也已实际完成选择文件、提交、查看 completed 和点击下载，下载文件与服务端产物哈希一致。网络及工艺源输入保存在任务私有的 sources 目录，便于任务结束后核对证据；公开下载仍受白名单限制。

## 四、发现并修复的问题

| 问题 | 本次处理 |
|---|---|
| Go 代理固定使用容器主机名 | 支持独立 V1/V2 服务地址配置，修正兼容路由与版本头 |
| 状态与下载响应不一致 | 修正批量查询转义、静态路由顺序、附件头、错误状态与服务不可用报告 |
| 并发限制异常被捕获后继续执行 | 使用 Redis 原子准入；容量不足或 Redis 不可用时明确失败 |
| 完全损坏的一源被另一有效源掩盖 | 改为逐源检查，不再误报为带警告完成 |
| 重复投递覆盖已完成状态 | 校验已有产物后复用；活动重复投递不清理原任务输入或释放其槽位 |
| 上传文件清理后无法复核证据 | 保留只读源副本及校验值，完成与核心失败时均可追溯 |
| manifest 可能被读到半写状态 | 临时文件写完后原子替换 |
| 前端构建依赖与静态路由问题 | ESLint 配置对齐 Next.js；本机代理提供静态页面的同源 API 转发 |

4. **分析能力**：没有真实抓包解析覆盖、因果推断、连续回放、工业准确率或大文件性能结论；旧版所有算法与图导入也未全面回归。

## 执行顺序与验收门槛

1. **M1 收尾**：共用逻辑记录读取规则；JSONL 坏行不影响后续引用；CSV 空行计入逻辑记录、多行字段作为一条记录；引用核对原始字段。双源入口任一源无事件即拒绝。建立运行内索引、统一完整性核验、发布前变更检测。新增回归和递增规模耗时/内存实测。主代理复核，M1 子代理实施。
2. **M2 可独立解析层**：单独 opt-in 合成 PCAP/PCAPNG 容器/帧适配器、明确支持矩阵、受限配置、可重建夹具和异常测试。协议能力以实际实现为界，不将容器读取等同 CIP 语义；旧入口继续可用。M2 子代理实施。真实字段参考、映射和对齐另列阻塞。
3. **M4 独立技术验证**：隔离命名空间的持久任务试验，验证领取、租约、fencing、心跳、取消及重试。优先真实 PostgreSQL 并发/过期测试；未接线部分明确标注。保留 Celery 默认和原产物；不在本轮验收前切换默认。M4 子代理实施。
4. **综合验收与提交**：主代理运行相关测试、检查跨模块接口和遗留服务回归，更新阶段状态、验收记录、具体缺口。代码和验收记录分阶段提交，后续记录引用实际代码 commit；不要求提交自引用 hash。
5. **随后推进**：M2 协议适配与独立字段参考 → M3 受控规则/反证及证据界面 → M4 内部鉴权 API/Worker 集成与故障矩阵 → M5 replay/独立评估 → M6 离线发布、恢复和回滚。等待数据期间先做不依赖标签的测试和基础设施；每项按退出条件验收。

# Explicit parsing profiles

`synthetic-demo.json` defines invented columns and assets for the synthetic test CSV only. It is not a SWaT mapping. `parse_process(path, profile, synthetic=...)` accepts an explicitly supplied dictionary with `timestamp_column` and `columns`; each column needs `tag` and `value_type` (`analog` or `state`). Optional fields are `unit`, `asset_id`, `state_map`, `timestamp_format`, `timezone`, `timezone_evidence` and `missing_values`. State values remain strings unless an explicit state map is supplied. Unmapped assets remain null/unresolved. Missing and invalid analog values remain null. No interpolation occurs.

Offset-bearing ISO timestamps provide their own timezone evidence. Naive timestamps require both a timezone and a nonempty evidence reference in the profile; no timezone is inferred from machine settings or SWaT's location. Ambiguous/nonexistent local times remain unresolved. CSV references use one-based logical data record numbers (header excluded), not physical line numbers. Network JSONL uses one-based record numbers and no frame number because it is not decoded packet evidence.

`swat/release-catalog.reference.json` is a metadata reference copied from `references/SWaT_collection_20261024/dataset_catalog.json` on 2026-10-24. It contains no raw data, verified device/column maps, thresholds or usable parsing configuration. A1/A2 cropping and A9/A10 naming differences remain unresolved. Each release must be independently checked against authorized raw files and its README before creating a usable profile. Public SWaT rules are candidate prior knowledge, never independent gold labels.

Raw PCAP/PCAPNG adaptation is explicitly unsupported pending independently checked decoding, reassembly and protocol coverage tests. JSONL support is exclusively for records marked `synthetic=true` and `record_type=synthetic_normalized_network`. It does not claim ENIP/CIP coverage. No real alignment or cross-source matching is implemented here.

Analysis input rejects reserved label/attack/ground-truth CSV column names even if they are not selected by the profile; selected column names and tag names are checked too. This is a conservative lexical guard, not proof that arbitrary renamed columns cannot contain labels. Network records reject all unknown keys and nonstandard JSON numeric constants. Missing network fields receive explicit `missing_*` quality reasons. A profile's optional `synthetic` flag must be an actual boolean matching the parser argument; falsey strings/numbers are rejected. Input SHA-256 is computed in bounded chunks; event lists are still accumulated in memory for this initial API.
